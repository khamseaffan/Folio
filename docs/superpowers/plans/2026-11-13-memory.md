# Memory Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Knowledge files and abilities per account, changed by the agent through operations, with `profile.md` in every model call and a read-only profile panel.

**Architecture:** Two new tables, each with its own module. Eleven new operations in the registry in `backend/app/operations.py`, all agent tools. A per-turn object counts the files opened in the turn. Three read routes feed a panel in the website.

**Tech Stack:** Python 3.13, FastAPI, psycopg 3, Pydantic, Postgres 18 full-text search, Next.js 16, React 19, TypeScript strict.

**Spec:** `docs/superpowers/specs/2026-11-13-memory-design.md`

## Global Constraints

- The only schema change is the two tables in the spec, exactly as written there. No other table, column, or constraint. `knowledge_file` has no `storage_key`.
- One module per table: `backend/app/knowledge_file.py` and `backend/app/ability.py`, each with `apply(connection, force=False)` in the style of `backend/app/thread.py`. `backend/app/migrate.py` runs both with `force=True`.
- Every SQL statement on these tables filters on `account_id`. The model never supplies an account id. A row of another account is reported as not found.
- No route writes memory. No memory operation is called by a button.
- No new model call. No new dependency in the backend or the frontend.
- A refused operation returns `{"ok": False, "code": ..., "error": <sentence>}` and never raises for bad input or a missing row.
- No AI or tool attribution anywhere. No em dashes anywhere. Comments only for a why that is not obvious. English copy.
- Frontend: `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`. Read `frontend/AGENTS.md` first.
- Backend checks, from `backend/`: `uv run ruff check .` and `uv run pytest`. Frontend checks, from `frontend/`: `npm run lint`, `npm run typecheck`, `npm run build`. The frontend has no test runner. Do not add one.
- Branches, stacked: `memory` (Tasks 1 and 2) on `usage-estimate`, then `profile-panel` (Task 3). Tasks 1 and 2 run in order in one worktree. Task 3 runs at the same time in another worktree, from `usage-estimate`, and is restacked onto `memory` after.

## Review Focus

1. A second account searches, reads, edits, or deletes with the first account's file name or ability id. Expected: not found, nothing changes. Tests in Task 1 and Task 2.
2. `edit_knowledge` with a `find` that appears twice, or not at all. Expected: refused, the file is unchanged, the answer says the count. Test in Task 2.
3. A sixth different file in one turn. Expected: refused. `profile.md` and a repeat of an already opened file do not count. A new turn starts at zero. Test in Task 2.
4. A search query with quotes, operators, or only punctuation. Expected: a result or an empty list, never an error. Test in Task 1.
5. A turn started before `profile.md` exists, and a turn after it is deleted. Expected: the call is sent without it, no error. Test in Task 2.

- `search_files` uses `websearch_to_tsquery('english', %s)` against `to_tsvector('english', body)`, ranks with `ts_rank`, and makes the snippet with `ts_headline('english', body, query, 'MaxWords=30, MinWords=10')`. `websearch_to_tsquery` never raises on odd input. A query that yields no terms returns an empty list.
- `byte_size` is `len(body.encode("utf-8"))`.
- Produces, in `app.ability`:

- The SQL, exactly:

```sql
-- knowledge_file.sql
CREATE TABLE IF NOT EXISTS knowledge_file (
    id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    account_id uuid NOT NULL REFERENCES account (id) ON DELETE CASCADE,
    name text NOT NULL,
    body text NOT NULL,
    byte_size bigint NOT NULL,
    created_at timestamptz NOT NULL DEFAULT now(),
    updated_at timestamptz NOT NULL DEFAULT now(),
    UNIQUE (id, account_id),
    UNIQUE (account_id, name)
);

CREATE INDEX IF NOT EXISTS knowledge_file_body_search
    ON knowledge_file USING gin (to_tsvector('english', body));

-- ability.sql
CREATE TABLE IF NOT EXISTS ability (
    id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    account_id uuid NOT NULL REFERENCES account (id) ON DELETE CASCADE,
    name text NOT NULL,
    body text NOT NULL,
    created_at timestamptz NOT NULL DEFAULT now(),
    updated_at timestamptz NOT NULL DEFAULT now()
);

CREATE INDEX IF NOT EXISTS ability_account_id
    ON ability (account_id);
```

- Changes, in `app.operations`:

```python
@dataclass
class Turn:
    opened: set[str]            # names of knowledge files read in this turn, without profile.md

@dataclass(frozen=True)
class Context:
    thread_id: uuid.UUID | None
    turn: Turn | None = None    # None for a route call

READ_LIMIT = 5
NO_FILE = "File not found."
NO_ABILITY = "Ability not found."
BAD_FILE_NAME = "A file name is 1 to 80 characters."
BAD_TEXT = "That text cannot be stored."
TOO_MANY = "This turn has already opened five files."
```

- `turn.py` makes one `Turn(opened=set())` per chat turn in `_write_reply` and passes `Context(prepared.thread_id, turn)` on every tool call of that turn.
- The eleven operations, all `agent=True`. Results on success:

| Name | Input fields | `ok` result |
| --- | --- | --- |
| `list_knowledge` | none | `{"files": [{"name", "byte_size", "updated_at"}]}` |
| `search_knowledge` | `query: str` | `{"matches": [{"name", "snippet"}]}` |
| `read_knowledge` | `name: str` | `{"name", "body"}` |
| `write_knowledge` | `name: str`, `body: str` | `{"name", "byte_size"}` |
| `append_knowledge` | `name: str`, `text: str` | `{"name", "byte_size"}` |
| `edit_knowledge` | `name: str`, `find: str`, `replace: str` | `{"name", "byte_size"}` |
| `delete_knowledge` | `name: str` | `{"name"}` |
| `delete_profile` | none | `{"deleted": <count>}` |
| `list_abilities` | none | `{"abilities": [{"id", "name", "body"}]}` |
| `write_ability` | `ability_id: uuid.UUID \| None = None`, `name: str`, `body: str` | `{"ability": {"id", "name"}}` |
| `delete_ability` | `ability_id: uuid.UUID` | `{"ability_id"}` |

- Rules:
  - A file name and an ability name are stripped and must be 1 to 80 characters with no null character, else `invalid` with `BAD_FILE_NAME`.
  - Any body or text with a null character is `invalid` with `BAD_TEXT`.
  - A missing file is `not_found` with `NO_FILE`. A missing ability, or another account's, is `not_found` with `NO_ABILITY`.
  - `append_knowledge` on an existing file with text joins with one newline when the existing body does not end with one.
  - `edit_knowledge`: count the occurrences of `find` in the body. Zero or more than one is `invalid` with the sentence `"The text to find appears {n} times in the file. It must appear exactly once."`. An empty `find` is `invalid` with the same sentence and n = 0.
  - `read_knowledge`: when `context.turn` is set and the name is not `profile.md` and not already in `turn.opened`, refuse with code `limit` and `TOO_MANY` once `len(turn.opened) == READ_LIMIT`; otherwise add the name after a successful read.
- `turn.py`, the system prompt: `_system_prompt` gains two parts, in this order after the harm line: the fixed memory instruction, then, when the account has a `profile.md`, the line `The person's profile:` followed by its body. The instruction, exactly:

```
You have a memory of this person made of Markdown files. When they tell you something about themselves or how they want things done, store it as a short plain statement in the file whose name fits, without asking. Manner and working preferences go in profile.md. Before you answer something about the person that you cannot see here, search the files. You can open at most five files in one turn. When two stored facts disagree, tell the person, say which one you believe should go, and delete it only after they agree.
```

  The profile is loaded where `_system_prompt` is called, for a new turn and for a retry.
- `main.py`, read routes. Each needs a session.

| Route | Success | Errors |

| `GET /knowledge` | 200, `[{"id", "name", "byte_size", "updated_at"}]` by name | 401 |

**Interfaces:**
- Consumes: the three read routes of Task 2.
- Produces, in `frontend/lib/api.ts`:

```ts
export type KnowledgeItem = { id: string; name: string; byte_size: number; updated_at: string };
export type KnowledgeFile = KnowledgeItem & { body: string };
export type AbilityItem = { id: string; name: string; body: string; updated_at: string };
export async function listKnowledge(): Promise<ApiResult<KnowledgeItem[]>>
export async function getKnowledge(id: string): Promise<ApiResult<KnowledgeFile>>
export async function listAbilities(): Promise<ApiResult<AbilityItem[]>>
```

- `profile-panel.tsx` exports `ProfilePanel`, which takes `onClose`, `onSignedOut(message)`, `onDown`, and `reloadKey: number`. It reloads its lists whenever `reloadKey` changes.

Behavior:
- A "Profile" control sits at the top of the chat area, beside the thread name, and also on the empty chat state. It toggles the panel.
- At 900 px and wider, the open thread and the panel sit side by side. Below that, the panel takes the place of the thread and shows a "Back to chat" control.
- The panel is a `section` labelled "Profile" with two headings: "Knowledge" and "Abilities".
- Knowledge is a list of file names, with `profile.md` first when present. Choosing a name shows that file's text below the list in a `pre` that wraps long lines, under the file name as a heading, with "Updated" and the time. The first file is shown when the panel opens.
- Abilities is a list. Each item shows the name and, below it, the text.
- Empty states, exactly: "Nothing is stored yet. Tell Folio something about you, and it appears here." for knowledge, and "No abilities yet." for abilities.
- A line under the heading, exactly: "You change these by telling Folio in the chat."
- `folio-app.tsx` raises `reloadKey` each time a chat turn ends, so a change by the agent shows without a refresh. If the file being shown is gone after a reload, the first file is shown.
- A 401 from any panel call returns to the public page as other calls do. A `down` result shows the system-down notice. Each is reported at most once per load.
- `toolStatus` in `folio-app.tsx` gains: `list_knowledge` "Looking at your notes", `search_knowledge` "Searching your notes", `read_knowledge` "Reading your notes", `write_knowledge`, `append_knowledge`, `edit_knowledge` "Updating your notes", `delete_knowledge` "Deleting a note", `delete_profile` "Deleting your profile", `list_abilities` "Looking at abilities", `write_ability` "Saving an ability", `delete_ability` "Deleting an ability".
- Settings and the profile panel are not open together. Opening one closes the other.
- Every control has a label and works by keyboard. No sideways scroll at 360 px. Use the existing palette and classes.
